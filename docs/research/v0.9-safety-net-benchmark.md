# v0.9 Safety-Net Benchmark

## TL;DR

This benchmark measured Kiji DistilBERT and OpenAI Privacy Filter (OPF) as direct detectors on the same 150-fixture coverage-loop corpus, using strict byte-span plus canonical-class recall as the headline safety metric. Kiji direct-detector macro strict recall stayed at `0.125000` in all three locale buckets (`0.875000` strict leak rate), while OPF improved direct recall to `0.364407` global, `0.255729` en-US, and `0.350668` de-DE. OPF is stronger Axis 4 evidence for direct detector coverage where its source-pinned Python install and larger local checkpoint are acceptable, but neither backend covers the full corpus: IBAN, credit-card, postal-code, Ethereum-address, and IP-address classes still leaked under this strict scorer.

## Methodology

The v0.9 matrix carried forward the v0.8 Kiji methodology: strict span recall counts a gold span as caught only when both byte boundaries and the canonical Gaze class match exactly. Partial overlap is a miss, and class mismatch is a miss because the manifest contract is typed. The headline strict leak rate is `1 - strict_recall`; precision and F1 are secondary diagnostics.

Both backends were run in direct-detector mode against raw coverage-loop fixture text. The OPF scorer cloned the Kiji scorer pattern in [`scripts/kiji-bench-scorer.py`](../../scripts/kiji-bench-scorer.py): same corpus loader, same per-fixture subprocess loop, same exact-match class accounting, and same per-class macro-average. OPF labels were mapped through the same closed convention as the Rust OPF adapter: `private_email -> Email`, `private_person -> Name`, `private_phone -> custom:phone`, `private_address -> Location`, `private_url -> custom:url`, `private_date -> custom:date`, `account_number -> custom:account_number`, and `secret -> custom:secret`.

Observer-residual mode remained `not_run_deferred` for both backends in this PR. That is the same scope line as the Kiji direct-detector run: residual measurement needs a separate cleaned-output harness that runs the deterministic Gaze pipeline first, then evaluates backend suspects against emitted manifest spans. Direct-detector cells are useful backend evidence, but they are not an end-to-end masking improvement claim.

## Kiji-vs-OPF Analysis

OPF outperformed Kiji on every locale-level direct-detector cell in this corpus. The gap is meaningful: OPF reduced strict leak rate from Kiji's `0.875000` to `0.635593` global, `0.744271` en-US, and `0.649332` de-DE. The biggest practical difference was not broad 26-class coverage in this synthetic corpus; it was OPF's strong exact recall on `Email`, `Name`, and most German/global `phone` spans. Kiji matched the `Name` proxy perfectly but missed the other measured classes under this strict byte-span/class scorer.

The result is still bounded evidence, not a blanket safety claim. OPF emitted many classes outside the current oracle support (`Location`, `custom:account_number`, `custom:date`, `custom:secret`, `custom:url`), which lowered precision but did not affect strict recall for supported classes. OPF did not catch `IBAN`, `credit_card`, `postal_code`, `custom:eth_address`, or `custom:ip_address` in this snapshot, so deterministic recognizers remain the reliability floor for those shapes.

For Axis 4, the routing conclusion is narrow: where a local OPF install, source-pinned Python dependency stack, and multi-GB checkpoint are acceptable, OPF is the better direct-detector evidence source than Kiji on this v0.9 corpus. Kiji remains useful as the smaller Apache-2.0 ONNX backend and as an independent observer, but the measured Kiji direct-detector cells do not support using it as the primary safety-net evidence for non-name PII in this corpus.
