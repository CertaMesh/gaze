# v0.9 Safety-Net Benchmark

## TL;DR

This benchmark measured Kiji DistilBERT and OpenAI Privacy Filter (OPF) in both direct-detector and observer-residual modes on the same 150-fixture coverage-loop corpus. Direct mode still shows OPF ahead of Kiji on strict recall (`0.364407` global, `0.255729` en-US, `0.350668` de-DE versus Kiji's `0.125000` in all three locale buckets). Observer-residual mode closes the deferred evidence gap: both backends catch all residual German name spans, both catch half of global residual spans, and OPF catches more en-US residual spans (`0.666667` versus Kiji `0.500000`) because it catches some residual phone spans. Latency is now measured separately in `safety_net_perf_snapshot.json`; the published one-shot CLI path is much slower for OPF than Kiji.

## Methodology

The v0.9 matrix carried forward the v0.8 Kiji methodology: strict span recall counts a gold span as caught only when both byte boundaries and the canonical Gaze class match exactly. Partial overlap is a miss, and class mismatch is a miss because the manifest contract is typed. The headline strict leak rate is `1 - strict_recall`; precision and F1 are secondary diagnostics.

Both backends were run in direct-detector mode against raw coverage-loop fixture text. The OPF scorer uses the same corpus loader, same per-fixture subprocess loop, same exact-match class accounting, and same per-class macro-average as Kiji. OPF labels were mapped through the same closed convention as the Rust OPF adapter: `private_email -> Email`, `private_person -> Name`, `private_phone -> custom:phone`, `private_address -> Location`, `private_url -> custom:url`, `private_date -> custom:date`, `account_number -> custom:account_number`, and `secret -> custom:secret`.

Observer-residual mode runs the deterministic Gaze pipeline first through [`crates/gaze-recognizers/examples/clean_for_bench.rs`](../../crates/gaze-recognizers/examples/clean_for_bench.rs), using the `core` + `core-extended` rulepacks and the fixture locale chain. The scorer excludes any gold span whose raw byte range overlaps an emitted manifest span, translates the remaining residual gold spans into cleaned-text byte offsets, runs the backend against `clean_text`, and counts only byte-exact plus class-exact matches. This is the strict residual definition: residual gold = `gold_spans ∩ NOT byte-overlapping with any manifest span`.

Latency capture is direct-mode only over 150 raw fixtures. The current timing scope is explicitly `per-fixture subprocess wall clock`; it includes fork/import/model load because both published wrappers are one-shot CLIs. It does not claim warm in-process inference latency.

## Kiji-vs-OPF Analysis

OPF outperformed Kiji on every locale-level direct-detector cell in this corpus. The gap is meaningful: OPF reduced strict leak rate from Kiji's `0.875000` to `0.635593` global, `0.744271` en-US, and `0.649332` de-DE. The biggest practical difference was not broad 26-class coverage in this synthetic corpus; it was OPF's strong exact recall on `Email`, `Name`, and most German/global `phone` spans. Kiji matched the `Name` proxy perfectly but missed the other measured classes under this strict byte-span/class scorer.

Observer-residual mode tells a narrower end-to-end story. After the deterministic rule floor runs, the residual set is mostly name spans plus the known uncovered en-US phone/global postal-code gaps. Kiji and OPF both catch the residual German name spans (`1.000000` recall) and both catch the global residual names but miss global postal codes (`0.500000` recall). OPF does better on en-US residuals (`0.666667` versus Kiji `0.500000`) because it catches some residual phone spans. Precision is lower in observer mode, especially for OPF global (`0.035971`), because the scorer still counts all backend predictions on cleaned text as candidates while recall only credits residual gold.

The result is still bounded evidence, not a blanket safety claim. OPF emitted many classes outside the current oracle support (`Location`, `custom:account_number`, `custom:date`, `custom:secret`, `custom:url`), which lowered precision but did not affect strict recall for supported classes. OPF did not catch `IBAN`, `credit_card`, `postal_code`, `custom:eth_address`, or `custom:ip_address` in direct mode, so deterministic recognizers remain the reliability floor for those shapes. In observer mode, neither backend closes the global postal-code residual.

Latency makes the routing conclusion explicit. With the current one-shot subprocess wrappers, Kiji median direct latency was `231.221 ms` per fixture while OPF median direct latency was `2880.084 ms`. These numbers include subprocess fork/import/model load and should not be used as warm model-service latency, but they are the honest cost of the checked-in scorer path.

For Axis 4, the routing conclusion is narrow: where a local OPF install, source-pinned Python dependency stack, and multi-GB checkpoint are acceptable, OPF is the better direct-detector evidence source than Kiji on this v0.9 corpus and the better en-US observer for residual phone/name gaps. Kiji remains useful as the smaller Apache-2.0 ONNX backend and as an independent observer, but the measured Kiji cells do not support using it as the primary safety-net evidence for non-name PII in this corpus.
