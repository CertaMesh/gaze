# v0.9 Gaze Pipeline Benchmark

## TL;DR

This benchmark extends the v0.9 SafetyNet matrix to full Gaze pipeline configurations, measuring strict detection quality and end-to-end latency on the 150-fixture coverage-loop corpus. In this run, both rule-floor configs measured successfully and produced identical strict leak rates: `0.375` for Global, `0.375` for en-US, and `0.250` for de-DE, with p50 latency below `0.4 ms` in all locale buckets. Pass-3 Kiji and OPF cells are intentionally `null` because the local benchmark commands were not configured; `+pass3-locale-aware` is also `null` because this stack exposes `LocaleAwareModelRegistry` but not a pipeline SafetyNet adapter.

## Methodology

The benchmark uses the same corpus and strict scoring contract as [`v0.9-safety-net-benchmark.md`](v0.9-safety-net-benchmark.md). A predicted span counts only when byte start, byte end, and canonical Gaze class match the oracle exactly. Partial overlap and class mismatch are misses because the manifest contract is typed and byte-addressed.

Pipeline execution is captured through [`clean_for_bench.rs`](../../crates/gaze-recognizers/examples/clean_for_bench.rs), which keeps one Cargo process alive and emits cleaned text, manifest spans, safety-net suspects, and timing metadata per fixture. The Python orchestrator [`scripts/gaze-pipeline-bench.py`](../../scripts/gaze-pipeline-bench.py) reuses [`scripts/safety_net_bench_lib.py`](../../scripts/safety_net_bench_lib.py) for fixture loading and strict metric calculation.

Pass timing is instrumented at observable boundaries. `pass1_ms` is the matching rule-floor pipeline wall clock. `pass2_ms` is `null` because none of the five locked configs enables Pass-2 NER. `pass3_ms` is the full-pipeline minus rule-floor delta for Pass-3 configs, and `0` for rule-floor configs.
