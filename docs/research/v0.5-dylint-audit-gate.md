# v0.5 Dylint Audit Gate

Phase D adds `GAZE_MODULE_ISOLATION`, a Dylint late-HIR lint that enforces the
audit-sink protected-path invariant with rustc name resolution. Phase E removes
the older `audit-metadata-only` syn walker after this gate has shipped and
proved stable for one release cycle.

## Toolchain Pins

- Nightly: `nightly-2025-09-18`
- Required components: `rustc-dev`, `rust-src`, `llvm-tools-preview`
- `clippy_utils` git rev: `20ce69b9a63bcd2756cd906fe0964d1e901e042a`
- `dylint_linting = "5.0.0"`
- `dylint_testing = "5.0.0"`
- Local/CI binary install: `cargo install --locked cargo-dylint dylint-link`

The spike rejected the plan-rev-2 candidate `nightly-2026-03-13` with
`clippy_utils` rev `f6d310...`; that pair did not compile against the rustc
internal APIs Dylint 5.0 needed.

## Commands

Verified working commands:

```console
$ cd xtask/dylint && cargo test --test ui
$ cd ../..
$ cargo dylint --workspace --all
$ cargo run -p xtask -- dylint-gate
```

Do not use `cargo dylint --workspace --all -- -D gaze_module_isolation` with
`cargo-dylint` 5.0. The `-D` flag is forwarded to `cargo check` and fails as an
unexpected argument. The lint is declared `Deny`, so `cargo dylint --workspace
--all` is the enforcing command.

The xtask wrapper verifies the UI fixture count, rejects `*_disabled.rs`
fixtures, and then runs the same clean workspace command. If `cargo-dylint` is
not installed locally, it prints a skip message; CI installs `cargo-dylint`
explicitly and therefore remains strict.

## Coverage Matrix

| Fixture | Bypass class |
|---------|--------------|
| `use_top_level.rs` | top-level `use gaze_audit::...` |
| `use_in_fn_body.rs` | function-body `use` |
| `use_in_impl_body.rs` | impl method-body `use` |
| `use_in_trait_default.rs` | trait default method-body `use` |
| `use_via_glob.rs` | glob import |
| `use_via_alias.rs` | aliased import |
| `use_via_macro_emit_callsite.rs` | macro defined outside protected path, invoked inside protected path |
| `use_via_macro_emit_defsite_negative.rs` | macro defined inside protected path, invoked outside protected path; clean control |
| `use_via_path_attr.rs` | `#[path = "..."]` module pulled from a protected module |
| `use_via_extern_crate.rs` | `extern crate gaze_audit` |
| `use_via_const_initializer.rs` | const initializer expression and function pointer type |
| `type_phantom_data.rs` | `PhantomData<gaze_audit::...>` |
| `type_struct_field.rs` | struct field type |
| `type_fn_param_return.rs` | function parameter and return types |
| `type_generic_arg.rs` | generic argument type |
| `trait_bound_where_clause.rs` | trait bound and where clause |
| `include_expands_forbidden_path.rs` | `include!()` expanding forbidden paths from a protected file |
| `clean_no_violation.rs` | clean protected-path baseline |

Diagnostics include the protected path, source span, resolved `DefId`, resolved
item path, usage class, and why the crate/item is forbidden.

## Phase E Migration

Phase E should decommission the syn walker only after Phase D has merged and
the new workflow has been green for one full release cycle. The removal should:

- delete `crates/xtask/src/audit_metadata_only.rs` or the inline walker code in
  `crates/xtask/src/main.rs`, depending on its final location;
- remove the `audit-metadata-only` workflow and related tests;
- keep `cargo-metadata-audit-isolation` as the complementary build-graph gate;
- keep `dylint-gate` as the protected-path resolver gate.
