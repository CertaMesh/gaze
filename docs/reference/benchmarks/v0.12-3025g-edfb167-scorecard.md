# #3025 slice G scorecard: shared gov-ID connector (`edfb167` vs `56e1a3d`)

This report measures the shared cue→value connector grammar for the five SSN /
government-ID recognizers (todo #3025 slice G) at commit `edfb167` — the head
that merges — against `main` at `56e1a3d`, the merge of slice U (#449). G is the
second #3025 slice and rebases onto U, so U's structured-containment rung is in
the base. `edfb167` is `e35d24d` (the original shared connector) plus the PR #450
review's B1 fix — Unicode/unbounded whitespace, [§B1](#b1-fix-ssnus-whitespace).
That fix is **corpus-invisible**: every corpus number below is byte-identical to
the pre-fix `e35d24d` candidate on every correctness integer, per-label row and
A4 category (verified across all three cells), so a single `edfb167` run is
sufficient and the two-run determinism proof lives in the retained `e35d24d`
candidate pair. It is evidence only: no accepted baseline was installed or
modified, and `--accept-baseline` was not used.

## B1 fix: `ssn.us` whitespace

The first shared connector fragment (in `e35d24d`) bounded every whitespace slot
to ASCII `[ \t\r\n]{0,4}`. Four of the five family rules were already
`[ \t]{0,4}` at base, so the fragment was a strict superset for them. But
`ssn.us`'s prior connector was `\s*[:#-]?\s*` — **unbounded and Unicode-aware** —
so the shared fragment *narrowed* it: an aligned plain-text column (`SSN:` + >4
spaces), a value more than four spaces after the cue, or an NBSP / narrow-NBSP /
em-space between cue and value (HTML/Word paste) was redacted at base and leaked
on the shipped default. The synthetic corpus contains no padded or
Unicode-spaced SSN spans, so the scorecard could not see it; the PR #450 reviewer
measured it with direct probes.

`edfb167` sets the fragment's whitespace atom to `\s` (Unicode) and makes every
whitespace slot unbounded (`\s*`), restoring `ssn.us`'s prior tolerance for all
five rules; the connector-word count is still capped at four. Re-measured on the
corpus in isolation: identical +1,744-byte recall and zero non-gold holdout
matches and zero A4 movement per recognizer — the change is corpus-invisible.
Its effect is pinned by three new fixtures (aligned-whitespace padding; NBSP /
em-space; a genuinely multi-token `ssn.us` phrasing) that are red under the
bounded fragment and green here; reverting only `ssn.us`'s connector turns the
drift guard (now naming `ssn.us`) and all three red. This scorecard confirms the
whole-pipeline corpus behaviour is unchanged by the fix: the JSON at `edfb167`
equals the committed `e35d24d` candidate on every correctness integer, per-label
row and A4 category across all three cells.

**Re-score note (the disjointness was measured, not assumed).** G's provisional
scorecard measured against `8d87468` (before U) gave the identical −1,802 and
the identical five per-label reductions. Re-scoring against the U merge
reproduces every one of those numbers byte-for-byte — G (gov-ID labels) and U
(URL / security-token) touch disjoint gold, so the primary axis is unchanged.
The one place the two changes couple is the Kiji safety net: U shortened URL
spans, which shifts clean text, and the `kiji-distilbert-ort` pass re-segments
neighbouring suspects a little differently. That coupling is visible only in the
Kiji false-positive **noise band** — it was +5 FP bytes against `8d87468` and is
−43 FP bytes here — and in the four re-segmented spans below. It is noise, in
the favourable direction, not signal; the gov-ID reductions and the worsened-span
set are identical across both bases.

## Residuals (the four Kiji worsened spans, individually)

All four are `kiji-distilbert-ort` safety-net name-suspects that re-segmented
when upstream clean text shifted (the known #2491 sensitivity); none is a shape
the connector rules matched:

1. **`ZIP` `T2E 4L4`** — base had one `kiji-distilbert-ort` name-suspect
   partially covering it; on the candidate that suspect is gone (2 bytes lost).
2. **`ZIP` `CB2 1DP`** — base covered it with two name-suspects, candidate with
   three differently-placed ones (2 bytes lost across the pair).
3. **`DATEOFBIRTH` `15. Mai 2023`** — base had one name-suspect over it,
   candidate none (3 bytes).
4. **`SURNAME` `Herr`** — base had one name-suspect, candidate none (4 bytes).

Each is a document where a nearby gov-ID number changed from raw to a token,
shifting the clean-text byte stream the Kiji pass scans; the safety net's
sub-word split of an unrelated neighbour moved by a few bytes. The
primary-pipeline trace items for these spans are unchanged, and none of the four
is a gov-ID shape.
