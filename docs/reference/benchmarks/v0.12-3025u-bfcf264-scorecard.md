# #3025 slice U scorecard: structured containment (`bfcf264` vs `8d87468`)

This report measures the structured-containment resolver rung
(`ConflictTier::StructuredContainment`, todo #3025 slice U) at commit
`bfcf264` against `main` at `8d87468`. It is the first of the #3025 slices and
the only one that changes arbitration for every class, so it was measured
alone, before any recognizer work. It is evidence only: no accepted baseline
was installed or modified, and `--accept-baseline` was not used.

## Headline

**On the shipped default (`full-stack-kiji-resolve`) leaked labelled bytes fall
31,995 → 30,461 (−1,534, leak rate 24.5583% → 23.3808%), fully covered
entities 10,008 → 10,102 (+94), zero-leak documents 1,111 → 1,126 (+15). The
`pass2-ner` cell moves by the same 94 entities (leaked 33,839 → 32,305). The
rule floor is byte-identical in every integer, every per-label row and every
A4 category.** Every one of the 94 changed arbitration outcomes is in the
intended direction: a builtin-class NER sub-token that used to evict a
`url.anchored` or `security_token.anchored` container now loses to it, and the
whole identifier is tokenised. Two-run determinism on the candidate is exact.

The label movement is exactly the mechanism the fix targets:

## The changed arbitration outcomes, span by span

The per-label rows above are aggregate. To show the *set* of outcomes that
changed, both trees were driven through `clean_for_bench` with the harness's
own loaders and every gold span was recorded together with the
`final_protection_trace` items overlapping it (the diagnostic instrument
reproduces every committed per-label row of both trees exactly). Comparing the
two dumps per gold span:

| Cell | Spans improved | Spans worsened | Winner-class transitions on the improved spans |
| --- | ---: | ---: | --- |
| `rule-floor-extended` | 0 | 0 | — (no NER pass; nothing to change) |
| `pass2-ner` | 94 (1,540 b) | 1 (6 b) | `URL`: organization → custom:url ×82, name → custom:url ×5, name+organization → custom:url ×3; `SECURITYTOKEN`: organization → custom:security_token ×2, location → custom:security_token ×1, name+organization → custom:security_token ×1 |
| `full-stack-kiji-resolve` | 96 (1,544 b) | 2 (10 b) | the same 94 as pass2, plus one `PASSWORD` and one `ZIP` span whose Kiji safety-net suspects re-segmented (see Residuals) |

Every improved span is a builtin-class NER sub-token that used to evict a
`custom:url` or `custom:security_token` container. That is the entire intended
direction of the rung and there is no transition of any other kind.

## Residuals

Three things did not move the way a perfectly clean run would, and each is
attributed:

1. **One `URL` span is 6 bytes worse (both NER-bearing cells).** Its NER
   `name` span *straddles* the end of the URL (`…/profile/JohnSmith. John` —
   the decoder joined the path tail, the sentence stop and the next word), so
   the pair is a *partial* overlap, which the rung deliberately leaves to the
   base ladder (scope test
   `partial_overlap_with_a_custom_span_still_uses_class_priority`). On the base
   the URL was already evicted by the organisation sub-token `mybank` (6 bytes
   covered) *and* the straddling name; on the candidate the URL first beats the
   contained organisation, then loses to the straddling name, so `mybank` is no
   longer covered. Four `URL` spans (111 leaked bytes) on the candidate are
   still evicted by straddling NER spans of this shape. Tracked as a follow-up
   design todo (custom-vs-builtin *partial* overlap, or NER decode across a
   sentence stop) rather than widened here; the rung's geometry is the
   permutation-invariant one.
2. **`PASSWORD` +2 and `ZIP` −2 bytes on the Kiji cell** are safety-net
   subword re-segmentation in two documents whose URL changed shape upstream:
   in one document a URL went from 4/20 bytes covered (organisation sub-token)
   to 20/20 (one URL token), and the Kiji pass over that document's clean text
   then split the neighbouring password differently (8 → 4 bytes covered by two
   `name` suspects); the other document gained 2 ZIP bytes the same way. The
   `redact_actions` +1 is the same document set. This is the known sensitivity
   of the Kiji resolve path to any upstream change (todo #2491), not a resolver
   outcome; the primary-pipeline trace items for those spans are unchanged.
3. **False-positive bytes rise by 169 (`pass2-ner`) and 187
   (`full-stack-kiji-resolve`); FP *documents* do not move in any cell, and
   the A4 negative corpus does not move at all — every category is identical
   in bytes and documents in all three cells.** The 169 is exactly seven
   `url.anchored` spans that touch no gold span (the corpus does not label
   these URLs): on the base each was represented by its NER organisation
   sub-token (52 FP bytes in total), on the candidate the whole URL is
   tokenised (221 FP bytes). Shape-normalised, the seven values are
   `aaaaa://aaaaaaaaaaaa.aaaaaaa.aaa.aa/aa/99999` (after "the dataset URL, "),
   `aaaaa://aaaaaaaa-aaaaaa-aaaaaaaa.aa` (after "auf der Website "),
   `aaaaa://aaaaaaa.aa` (after "Community auf "),
   `aaa.aaaaaaaaaaaa.aa.aa` (after "the bank's website at "),
   `aaaaa://aaaa-aaaaaa.aa/aaaaaaaaaaaa` (after "die Webseite "),
   `aaaaa://aaa.aaaaaaaaaaaa.aa` (after "auf unserer Website "), and
   `aaaaa://aaa.aaaa.aa/aaaaaaaaaaaaaaaaaaaa` (after "auf ihrer Webseite ") —
   each a genuine URL the gold annotation missed. This is the gold-noise
   exception to the invariant ratchet documented in
   [`README.md`](README.md#zero-leak-production-goals): zero A4 movement plus an
   enumerated list the reviewer can re-check span by span. The remaining +18
   bytes on the Kiji cell are the same Kiji re-segmentation as residual 2
   (284 suspect items added, 249 removed, net +187 = 169 + 18).

## Determinism and gates

Run 2 (`--skip-build`, same binary, `dirty = false`) reproduces run 1 exactly:
the complete `_run_correctness_counts` integer set is equal in every cell and
`compare_scorecards(run 2, run 1)` returns `regression.passed = true` with zero
failures. Wall clock per cell, run 1 / run 2: rule 8 s / 6 s, pass2 171 s /
165 s, Kiji 465 s / 461 s.

Gates at `bfcf264` under the pinned toolchain, worktree-local `target/`, exit
codes: `cargo fmt --all -- --check` 0, `cargo clippy --workspace --all-features
--all-targets -- -D warnings` 0, `cargo test --workspace --all-features` 0
(134 test binaries, 0 failures), `xtask fixture-citation-lint` 0,
`bundle-tokenization-drift` 0, `locale-cue-bundle-coherence` 0,
`recognizer-composition-validator` 0.

Probe and mutation: the pipeline test
`ner_sub_token_does_not_split_a_structured_credential` was written first and is
RED on the unfixed resolver (clean text `aws key <…:Organization_1>ODNN7EXAMPLE
end` — the credential tail ships raw); with the rung it is GREEN together with
the two resolver tests that assert the container wins in both arrival orders
and under multi-overlap. Disabling the rung after the commit turns exactly
those three RED again (20 passed / 3 failed); restoring and rebuilding gives
23 passed / 0 failed with a clean tree.
