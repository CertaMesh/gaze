# MCP host context verification

## Pipeline assembly reuse

Clones of one host selection share a bounded assembly profile. Session audit
identity, resident registry identity, full policy, rulepacks and locale chain
must match to reuse it. A profile change replaces the slot; a `OnceLock` admits
one construction for concurrent users of that profile. Cached assembly failures
and poisoned slot locks fail closed. Each call still parses the original
context, admits arguments and applies fresh guess exclusions.

The counter regression requires one construction across six real dispatches,
including a guessed first response followed by an unguessed response that must
be protected and restored. Separate regressions cover concurrent construction,
profile invalidation and cached failures. The `rebuild-context-pipeline` mutant
forces rebuilding and must compile, execute and fail the named counter test.

## Default clean equality

[Value-free equality report](mcp-host-clean-equality.json).

The comparison passed 2,144 cases: 1,072 without policy and 1,072 with setup
policy. Every invocation exited successfully. Each side reported 767 detections
in total. Both one-byte mutants were detected. The generated policy hashes match.

The baseline is `2fc435adfcec118ccb3fd2f38a1a80de625d570c`.
The measured source is `0dc40595cea3c64b7fbaf2f527dcb7d061298059`.

The release comparison uses 1,072 fixed inputs in each of two modes: no policy,
and the default policy generated by each binary's own `gaze setup`. The binaries
come from separate prepared Anvil worktrees. Both CLI binaries use default Cargo
features plus `mcp`, with locked dependency resolution. The report pins their hashes, source
commits, the input manifest, the driver, and both generated policies.

Only random session prefixes inside complete emitted tokens are normalized.
The token grammar is anchored to each complete entry token. All other bytes in
`clean_text`, `entries`, `stats`, and `leak_report` are preserved and compared as
canonical JSON, together with the exit code. Random owner-secret session blobs
are excluded. This is equality of the documented projection, not raw whole-JSON
equality or full-corpus detection certification.

A candidate-output mutant replaces one ASCII character in `clean_text`.
The driver checks that the serialized projection changes by exactly one byte
and that the same comparator rejects it in both policy modes.

The fixed set consists of detector drift lines, 1,024 benign English/German
counterweights, policy-equivalence and capture-reuse fixtures, the complete drift
fixture, and README. The input manifest pins every source hash and case count.

Hardware: Apple M5 Max, 18 logical CPUs, 64 GiB RAM, arm64, macOS 26.5.

All 900 calls were validated, with zero errors. Each path validated 300 calls,

| cli-absent | 0.721 [0.643, 0.789] | 1.235 [0.979, 5.667] | 55.953 [51.000, 63.078] |

The release measurements cover three distinct paths:

| Path | Tool | Manifest store | Context |
| --- | --- | --- | --- |
| CLI stdio | `gaze_read_text` | Filesystem | Absent |
| Embedded rmcp stdio | Synthetic `lookup` | No I/O | Absent |
| Embedded rmcp stdio | Synthetic `lookup` | No I/O | Present, 32 short fields |

Stock CLI stdio has no host-private context channel. The embedded example uses
host-owned process configuration and the same core assembly and `PiiEnvelope`
as CLI serve. It does not add a production context injection switch.

The embedded workload supplies 32 short argument scalars and stays within the
default byte and scalar caps. Each path runs in five fresh server processes,
with ten warmup calls and fifty timed calls per process. Embedded Absent and
Present alternate order. Requests are sequential at concurrency one.

Each timed interval starts before writing a JSON-RPC `tools/call` request and
ends after receipt of its complete response. The driver checks every response
outside the timed interval. It verifies preservation for Absent and tokenization
of the unguessed host record for Present. The tool catalog and MCP handshake
are checked before timing.

Peak RSS comes from `wait4` for the exact server process, including startup and
warmup. The report converts Darwin's byte units directly. Server and driver CPU
seconds and shared-machine load are recorded. CLI includes manifest filesystem
work, so its measurements cannot isolate context overhead.

These are observed latencies and memory use for one fixed sequential workload.
There is no pass/fail threshold, no claim of a speedup, and no resident neural
model claim. Both paths use the core pipeline without optional neural safety nets.

## Reproduction

The input manifest is
[`scripts/verification/clean-equality-inputs-v1.json`](../../scripts/verification/clean-equality-inputs-v1.json).
It reuses the 1,072-case set from the daemon verification.

The named `mcp-host-release` Anvil check holds `workspace-build`. It builds both
CLI binaries and the embedded example with two jobs and locked dependencies.
`GAZE_CLEAN_BASE_WORKTREE` selects a prepared, clean, detached baseline worktree.

```sh
GAZE_CLEAN_BASE_WORKTREE="$BASE" anvil check mcp-host-release \
	--allow-expensive --lock-wait 90m --json
anvil run -- python3 scripts/verify_clean_equality.py \
	--base-bin "$BASE/target/release/gaze" \
	--candidate-bin target/release/gaze \
	--base-sha "$BASE_SHA" --candidate-sha "$CANDIDATE_SHA" \
	--output target/clean-equality.json
anvil run -- python3 scripts/measure_mcp_host_context.py \
	--cli-bin target/release/gaze \
	--host-bin target/release/examples/host_context_measure \
	--output target/mcp-host-latency-rss.json
```

The latency capture requires the Solo `bench-machine` lease. Heavy work follows
the operator's time window, free-memory floor, and disk floor. The fixed workload
is defined in the committed driver and example. The report pins their measured
source and binary hashes. Evidence-document commits do not alter runtime code.
